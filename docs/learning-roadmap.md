# План подготовки системного администратора на 12 недель

План рассчитан на 10–12 часов практики в неделю. Результат каждой недели — проверяемый артефакт: схема, конфигурация, скрипт, снимок мониторинга или отчёт об инциденте.

## Недели 1–2. Сети и диагностика

- повторить OSI/TCP-IP, IPv4, маски, шлюз, ARP, DNS, DHCP, NAT;
- отработать `ipconfig`, `ping`, `tracert`, `nslookup`, `Test-NetConnection`, `route print`, `netstat`;
- собрать две VLAN в Packet Tracer, настроить trunk/access и межсетевую маршрутизацию;
- уметь объяснить путь DNS-запроса и найти проблему «IP доступен, имя не открывается».

**Результат:** схема сети, таблица адресации и пять разобранных неисправностей.

## Недели 3–4. Windows Server и Active Directory

- развернуть `DC01` и `CLIENT01` по инструкции этого репозитория;
- создать лес `corp.lab`, OU, пользователей и группы;
- настроить DNS, DHCP, присоединение клиента к домену;
- выдать доступ к общей папке через группы, проверить NTFS и Share permissions;
- создать GPO и проверить применение через `gpresult /r` и журнал событий.

**Результат:** работающий домен и заполненный чек-лист из [validation.md](validation.md).

## Недели 5–6. Linux и автоматизация

- пользователи, группы, права, `sudo`, systemd, журналы, SSH;
- сеть: `ip`, `ss`, `dig`, `curl`, `tcpdump`;
- Bash и PowerShell: параметры, обработка ошибок, идемпотентность, `-WhatIf`;
- повторить `Traffic Filter Lab`: Docker-сети, UFW, iptables, Nginx.

**Результат:** два диагностических скрипта и отчёт о прохождении сетевого стенда.

## Недели 7–8. Виртуализация, Docker и резервное копирование

- checkpoints Hyper-V, виртуальные коммутаторы, NAT;
- Docker volumes, networks, healthchecks, Compose;
- правило резервного копирования 3-2-1, RPO/RTO;
- пройти backup/restore drill в `Sozyv Ops` и зафиксировать время восстановления.

**Результат:** восстановленная тестовая база и короткий runbook аварийного восстановления.

## Недели 9–10. Zabbix и наблюдаемость

- поднять Zabbix из этого репозитория;
- подключить Windows Agent 2 на `DC01` и `CLIENT01`;
- добавить проверки CPU, памяти, диска, доступности DNS и SMB;
- создать триггер нехватки места и провести тестовое срабатывание;
- сравнить назначение Zabbix с Prometheus/Grafana из `Sozyv Ops`.

**Результат:** четыре monitored items, два trigger и скриншот тестовой проблемы с последующим восстановлением.

## Недели 11–12. Поддержка и собеседование

- потренировать цикл заявки: уточнение, приоритет, диагностика, решение, проверка, запись в базу знаний;
- решить 15 типовых кейсов: DNS, DHCP, GPO, учётная запись, права на папку, диск, служба, сеть;
- подготовить рассказ по каждому GitHub-проекту по схеме «задача — решение — проверка — чему научился»;
- провести две пробные встречи: техническая и HR;
- откликаться только после адаптации верхней трети резюме под вакансию.

**Результат:** база из 15 решений, трёхминутный рассказ о проектах и журнал откликов.

## Еженедельный режим

- 60% времени — лабораторная практика;
- 20% — теория и официальная документация;
- 10% — разбор ошибок и заметки;
- 10% — резюме, GitHub и отклики.

Не переходите дальше, пока не можете воспроизвести результат без пошаговой подсказки и объяснить, как проверить, что он действительно работает.
